最終の構成(`src/controller/llm_controller.py` のプロンプト・検証を含む)で `scripts/run_b_suite.sh` を実行した結果。
成功の定義: 目標の箱の手前で止まり、箱の中心から 2m 以内にいる。

| 初期位置 (x, y, yaw) | 指示文 | 結果 | 箱中心までの距離 [m] | 判断回数 | フォールバック |
|---|---|---|---|---|---|
| 0, 0, 0 | 青い箱に近づいて止まれ | 成功 | 1.53 | 61 | 0 |
| 0, 2, 0 | 赤い箱のところまで行って、着いたら止まって | 成功 | 1.36 | 70 | 0 |

| -2, 0, 3.14(箱と逆向き) | 赤い箱に近づいて止まれ | 成功 | 1.24 | 139 | 0 |

- 動画に使った 2 回の走行(開始位置 0, 0, 0、最終の構成で撮り直し): 赤 1.30 m(48 判断)/ 青 1.50 m(58 判断)で停止。どちらもルールと食い違う判断は 0 件。
- 指示文を「赤→青」に変えると、同じ開始位置から行き先が分かれる。
- LLM に接続できない場合(ポートを誤指定)は、全ステップが stop にフォールバックし、ロボットは動かない。
- 同じ条件でも LLM 応答のタイミングで軌跡は変わる(確率的)。

## LLM の判断精度(`tests/eval_llm.py`、正解ラベル付き観測 32 件)
| モデル | 正解 | 備考 |
|---|---|---|
| qwen3.5:4b | 23/25(25 件時点) | 青の判断が不安定(目標でない色につられる) |
| qwen3.5:9b(採用) | 29〜31/32(実行ごとに揺れる) | 約 1 秒/回。言い回しを変えた未知の指示 6 件は正解 |

注意: プロンプトの few-shot 例の一部は評価ケースと近い型で、評価の件数も少ない。汎化を保証する値ではない。
プロンプトに例を足すと別の型が揺れることがあり、調整は評価セットで確認しながら行った。

## 開発中に見つかった問題と対策(考察用)
1. **構造化出力(JSON スキーマ指定)が使えない**: qwen3.5 では Ollama の `format` が "structured output is unavailable"。→ プロンプトで JSON を要求し、こちらで検証。不正なら stop にフォールバック。
2. **4b は目標でない色の観測につられる**: 青を指示したのに赤を見て前進し 30m 以上走り去った。評価セットに失敗パターンを追加し、9b に変更して解消。
3. **距離を画像の幅で測ると、斜めから近づくと壊れる**: 箱が画像端で切れて幅が小さく測れ、停止できず接触。→ 高さ(0.5m、端で切れない)に変更。
4. **LLM の応答待ち中、ロボットは直前の指令で動き続ける**: 応答が遅れると進みすぎて接触。→ タイムアウトを 3 秒に短縮、走行前にモデルをウォームアップ、`keep_alive` を延長。
5. **「停止してください」という語につられた早すぎる stop**: どちらの箱も見えない状況で stop し、箱の約 4m 手前で止まった(最終確認で発見)。→ 例を追加し、「到達した箱がないのに stop」は無効な出力として扱う検証を追加。
6. **安全層**: どの箱でも高さ 130px 以上(約 0.7m)なら LLM の判断に関わらず強制停止。
